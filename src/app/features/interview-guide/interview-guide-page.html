Essential CLI commands

From the workspace root, these commands install NgRx, start the app, and generate common Angular files.

# Add the NgRx packages used in this sample (Angular 21 / NgRx 21)
npm install @ngrx/store@^21 @ngrx/effects@^21 @ngrx/entity@^21 @ngrx/router-store@^21 @ngrx/store-devtools@^21 @ngrx/signals@^21

# Start the app and build it
npm start
npm run build

# Run unit tests
npm test

# Generate an Angular feature component and service
ng generate component features/example
ng generate service features/example/data-access/example-api

State flow in this project

  1. ComponentDispatches a descriptive intent action, such as Task Creation Requested.
  2. EffectCalls the demo API and maps success or failure to a serializable action.
  3. ReducerUses Entity Adapter to immutably update normalized task state.
  4. SelectorDerives visible tasks and progress without storing duplicate computed data.
  5. ComponentReads selector values as signals with Store.selectSignal().

Questions to practice out loud

What problem does NgRx solve, and when would you avoid it?

It makes shared state transitions explicit and predictable. For isolated, short-lived UI state, a local signal or component state is often simpler.

Why keep reducers pure and immutable?

Pure immutable transitions are deterministic, easy to test, compatible with memoized selectors, and observable by DevTools.

How do an effect and a reducer differ?

A reducer synchronously calculates the next state. An effect handles side effects such as HTTP calls and dispatches a follow-up action.

How do you choose an RxJS flattening operator in an effect?

Choose based on concurrency: switchMap cancels stale work, concatMap queues, mergeMap allows concurrency, and exhaustMap ignores new triggers while work is active.

Why use Entity Adapter and selectors?

Entity Adapter standardizes normalized collection updates. Selectors encapsulate and memoize derived reads so components do not duplicate state logic.

What belongs in the store?

Serializable state that benefits from sharing or predictable transitions. Avoid services, subscriptions, class instances, and values that can be derived.

Interview tip Explain the trade-off first, then trace one real action in this app from dispatch through the effect and reducer to the selector.
